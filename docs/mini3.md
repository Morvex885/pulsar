# Мини 3 (`bergamot`) — экспериментальный профиль

Что наблюдалось на двух Мини 3 и что проверено в работе pulsar, а что нет. Как pulsar использует
эти данные, здесь не описано — это профиль [`MINI3`](../satellite/crates/pulsar-core/src/model.rs):
поведение кода — в коде, обоснования — в комментариях у кода. Это данные контрибьютора, не
авторитетные (авторитетны только Миди и Лайт 2, [hardware.md](hardware.md)).

Статус: экспериментальный; ручной запуск демона и воспроизведение проверены на одной станции.
Не Мини 3 Pro. Обследованы две Мини 3 с одинаковой прошивкой
`0.369.1.50.4794652521.20261021.117` и совместимостями
`yandex,bergamot-evt1`, `yandex,bergamot`, `amlogic, axg`.
Акустическое качество AEC отдельно не измерялось.

## Подтверждено штатной системой

| Узел | Наблюдение / источник |
| --- | --- |
| ABI | Linux 4.9.68 aarch64, загрузчик `/lib/ld-linux-armhf.so.3`, glibc 2.30 (armhf-сборка нацелена на glibc 2.23 Мини; на Мини 3 после перехода на эту цель не запускалась) |
| RAM | MemTotal около 238 МиБ |
| Захват | `/etc/asound.conf`: `multi_capture` из `hw:0,1`, 8 физических каналов: микрофоны PDM0–2 на каналах 0/1/2, канал 6 — `HW feedback (TDMB_IN0)`, обратный сигнал усилителя (референс динамика для VQE) |
| VQE | пресет `bergamot`, 3 микрофона + 1 референс: 768 кадров захвата @ 48 кГц → 256 сэмплов @ 16 кГц, 16 мс |
| Воспроизведение | ALSA `speakers` → `dmix_speakers` → `hw:0,0`, стерео 48 кГц; у `dmix_speakers` `ipc_key 1024` (= 0x400) |
| Громкость | `Master` моно, 0..255; карта штатного конфига 0→0, 1→33, 20→255 |
| Кольцо | `/dev/fb0`, имя `logo`, 6×1, 24 bpp (AW21018); `bergamot:<цвет>:logo0..5`, trigger `ledfb-logo`; отдельного логотипа нет |
| Часы | продаётся с часами (AW21036) и без них; `bergamot:white:clock<A..G><0..3>`, `DH`/`DL`, `DM`, `DEGREE` |
| Кнопки | evdev `aw933xx`, в битовой маске есть действие и громкость вверх/вниз |
| Отключение микрофонов | evdev `gpio-keys`, `SW_MUTE_DEVICE`; начальное состояние прочитано |
| Датчик освещённости | IIO `ltr308als01` |
| Earcons | `common/spotter_start.mp3`, `spotter_cancel.mp3`, `volume_sound.mp3`, `timer.wav` (по заголовку это MP3), `ru-RU/playback_error.mp3` [inference: GStreamer прошивки декодирует MP3, раз штатные earcons — MP3; в логе pulsar не проверено] |
| Модели спотера | штатные каталоги `spotter_models/activation/alisa` и `spotter_models/command` существуют |

В обеих станциях совпали SHA256 `libyandex_evil.so`, `libtflite.so`, `quasar.cfg` и
`asound.conf`. Проприетарные библиотеки, модели, сырые конфиги и персональные сведения
в патч не входят (общее правило — [AGENTS.md](../AGENTS.md#git), «Git»).

## Проверки в работе

Проба ABI ALSA (`alsa_abi_probe`) прошла (`alias=yes`). За 20 с прогона фронтенда: 1248 аудиоблоков
по 256 сэмплов, 624 музыкальных кадра, 0 потерь; музыкальные кадры — 31,23 в секунду.
HA подключился по ESPHome API с автоматической выдачей ключа Noise. TTS через HA доходит
до EOS. Очередь Music Assistant играет через Sendspin FLAC 48 кГц стерео → ALSA
`speakers`: 60,5 с записи в устройство, 0 xrun, в том числе с TTS HA поверх музыки.
Пауза и продолжение, громкость и стоп проверены через Music Assistant; после рестарта сервера
Music Assistant переподключение произошло автоматически. Это не акустическое измерение AEC или
распознавания речи.

## Не проверено

- AEC при музыке и ответе (сравнение сырых сигналов микрофонов и выхода VQE).
- Сырой захват по каналам (`frontend_probe --record`): какой канал какой микрофон.
- Длительная работа захвата и VQE (короткий 20-секундный прогон без потерь не доказывает суточную
  устойчивость).
- Цвета и порядок зон кольца.
- Физические кнопки действия и громкости и переключатель отключения микрофонов, включая запуск с
  выключенными микрофонами.
- Стоковый init-скрипт прошивки (в цепочке загрузки не записан).
- Часы, их яркость и датчик освещённости; вариант без часов.
- MP3-earcons в логе pulsar.
- Длины пре-ролла (строки `wake timing:`): в профиле — длины Лайт 2 во времени, не замерялись.
- Установка через `pulsar-install` от начала до конца и автозапуск после перезагрузки.
