# Миди (`cucumber`)

Станция мейнтейнера, данные авторитетны. Железо —
[вики](https://hackalice.me/devices/station-midi/); здесь только то, чего там нет
([AGENTS.md, «Документация»](../AGENTS.md#документация)). Zigbee —
[zigbee.md, «Радио Миди»](zigbee.md#радио-миди).

## Userland и хранилище

Userland aarch64, glibc 2.36; на части образов прошивки 32-битный userland armhf, glibc 2.30.

## Звук

- Захват: `hw:0,2`, 8 каналов @ 96 кГц, S16_LE: микрофоны 0–3, референс динамика 4–7.
- Воспроизведение: `speakers`; громкость — softvol «Master Playback Volume» на `speakers`.
- VQE: пресет `cucumber`: 4 микрофона, 4 референса, 96 кГц, чанк 3072 → 512 @ 16 кГц.
- Спотеры: `alisa` — типы 0, 3, 4; `command` — тип 0.
- alsa-lib 1.2.10, версионированная —
  [hardware.md, «alsa-lib: версионированная и неверсионированная»](hardware.md#alsa-lib-версионированная-и-неверсионированная).
- Замеры ALSA: dmix, который опустел и запустился заново, теряет ~60 мс следующих записанных
  сэмплов, а `snd_pcm_delay` показывает на ~70 мс меньше, чем на самом деле осталось доиграть.

### Входы спотера и проверка усиления

Проверено 2026-11-03 на armhf-прошивке с моделью
`ru-RU-cucumber-alisa-23May25`: текущий SDK-путь maind преобразует типы C API спотера
0–5 в выходы C API VQE `[6,7,5,8,2,3]`. Для `alisa` (типы `[0,3,4]`) это
`[6,8,2]`: основной обработанный сигнал, BNR, синхронизированный основной микрофон.
Сопоставление установлено по конвертерам maind и подтверждено его конфигурацией
`vqe_main`, `vqe_bnr`, `main_mic_sync`. Старый путь maind использует другую нумерацию;
инвертировать его таблицу как таблицу текущего SDK нельзя.

На сохранённом захвате обнуление микрофонов 0 или 1 меняло BNR-выход 8, но оставляло
выходы 2/6/9 побитово прежними; обнуление микрофона 2 не меняло эти четыре выхода.
При обнулении микрофона 3 все четыре выхода были нулевыми. Это наблюдение для данной
записи и состояния VQE, не постоянная схема выбора микрофонов.

Проверка усиления: одна новая акустическая запись с четырьмя голосами (Vosk TTS
`male_12`, `female_1`, gTTS, macOS Milena), по четыре обращения и две контрольные фразы
на голос. Исходная речь нормализована к целевому RMS активной части −20 dBFS с ограничением пика −6 dBFS;
источник — Mac на 38%. Все варианты получали один захват. Усиление одинаково для всех
трёх каналов, после VQE и до квантования в S16 с округлением к ближайшему чётному.

| Раскладка / общее усиление | Подтверждено из 16 |
|---|---:|
| `[9,2,6]`, ×1 | 11 |
| `[6,8,2]`, ×1 | 13 |
| `[6,8,2]`, ×2 или ×5 | 14 |
| `[6,8,2]`, ×10, ×20, ×30 или ×50 | 16 |

Повторы ×1/×10/×50 совпали по событиям, временам и счётчикам насыщения. Ложных
подтверждений на восьми контрольных фразах и вне окон обращений не было. После первых
двух секунд насыщения не было; стартовый выброс насыщался, сильнее при большем усилении.
×10 — минимальная успешная **из проверенных ступеней**, не универсальный оптимум.
На более ранней записи те же голоса дали 8/16 с `[9,2,6]`, 14/16 с `[6,8,2]` ×1 и ×10,
15/16 с ×50; возможный фоновый разговор не был инструментально подтверждён.

Проверка не покрывает шум, AEC, другие позиции, живые голоса и длительный бытовой фон;
maind целиком не запускался. Для других моделей станции, wake-модели `yandex` и командного
спотера соответствующий замер усиления не выполнен.

## Светодиоды и часы

- В `/dev/fb0` (кольцо) и `/dev/fb1` (логотип) байты лежат в порядке B, G, R.
- Яркость часов задаётся `current` чипа; центральной точки у часов нет.
