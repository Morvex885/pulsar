# Протокол станций

Правила для агентов и людей, которые тестируют pulsar на живых станциях: что разрешено, в каком
порядке и при каких условиях. Здесь нет описания команд [`tools/station.sh`](../tools/station.sh)
(помощник реализует эти правила; что делает каждая команда — в его usage и комментариях) и фактов о
железе (вики и docs моделей, указатель — [hardware.md, «Модели»](hardware.md#модели)): поведение
кода — в коде, обоснования — в комментариях у кода.

- **Адреса.** Адреса станций (`PULSAR_<X>` в окружении) в репозиторий не попадают (общее правило —
  [AGENTS.md](../AGENTS.md#git), «Git»). Если переменной нет — статус `заблокирован: нет PULSAR_<X>`.
- **Lock.** Всё, что меняет состояние станции, — только под своим lock. По метке `PULSAR_TAG`
  должно быть видно, чья это работа (ветка, задача).
  - Срок заявляется честно; живая подмена — минимум 30 минут (скрипт этого не проверяет).
  - Чужой lock снимается только командой `break-lock`.
  - Порядок завершения сессии: `test-stop` (если запускали) → `start` или `restore` → `cleanup` →
    `unlock`.
- **Аппаратные тесты** (аудио, плеер, Sendspin-sink, LED, часы, ввод, датчик, радио) и **любые
  тесты ESPHome API** (`api_selftest`, тестовый экземпляр) — только при остановленном сервисе
  (`stop`; [AGENTS.md](../AGENTS.md#безопасность-станций), «Безопасность станций»):
  - если `stop` отказывает, потому что станция в Yandex-режиме, — статус
    `заблокирован: станция в Yandex-режиме`, сообщить владельцу;
  - после теста — `start`.
- **Сетевые тесты без API** (mDNS-проба, арбитраж, HTTPS) можно гонять при работающем демоне:
  - только на альтернативных портах (16054 и т. п.);
  - mDNS — только с сервисным типом `_pulsartest._tcp`, никогда не `_esphomelib._tcp` и не
    `_sendspin._tcp`;
  - к портам 6053, 6638, 8928 живого демона не подключаться (список портов —
    [«Порты и тестовый режим»](architecture.md#порты-и-тестовый-режим)).
- **Тестовый экземпляр демона.** Только при остановленном сервисе (пункт «Аппаратные тесты») и
  только на смещённых портах; клиенты ESPHome API подключаются к нему (или к `api_selftest`), не к
  живому демону. Перед `start` его останавливают (`test-stop`). Порядок команд — skill
  `station-test`.
- **Убитый во время звука процесс.** Тест, который убивает играющий процесс
  (`kill -SEGV`/`kill -9` тестового экземпляра или probe во время звонка, TTS, музыки), оставляет
  устаревший dmix-lock, и станция молчит до перезагрузки
  ([«Зависший dmix lock»](hardware.md#зависший-dmix-lock)). После такого теста — обязательно
  очистка (`cleanup`); вручную — только по [«Зависший dmix lock»](hardware.md#зависший-dmix-lock).
- **Живая подмена**: `swap <бинарь>` → наблюдение за логом → обязательно `restore`.
  - Миди в роли `pulsar-coordinator`: живая подмена — только при двух условиях:
    1. Read-only чтение `tools/deconz_read.py` тестового экземпляра (16638) совпадает с чтением
       `zigbee_probe` установленной версии при остановленном сервисе: device state, MAC, PAN,
       ext PAN, канал и NWK update id. Порт `zigbee_probe` передаётся явно — `zigbee_probe 16639`
       (без аргумента он слушает 6639).
    2. Владелец подтвердил свежий бэкап Z2M/ZHA.
    - Без подтверждения подмена на Миди не делается, пункт уходит в чек-лист владельца.
- **Громкость.** Предел для тестов со звуком и согласие владельца —
  [AGENTS.md](../AGENTS.md#безопасность-станций), «Безопасность станций». Перед сценариями со звуком
  проверить громкость: на Миди/Лайт 2 — `amixer -c0 cget/cset name='Master Playback Volume'`, на
  Мини аппаратной шкалы нет ([mini.md, «Звук»](mini.md#звук)) — через API (`volume`).
- **Радио Zigbee.**
  - Читать — только сырым скриптом `tools/deconz_read.py`. Подключение вытесняет текущего
    deCONZ-клиента (Z2M/ZHA отключаются), поэтому скрипт запускается только против тестового
    экземпляра (16638) или порта `zigbee_probe` при остановленном сервисе, никогда против 6638
    живого демона. zigpy, `ControllerApplication`, write parameter и смена network state запрещены.
  - Прошивать — только образ текущей роли из `state.conf`
    ([«Роли и state.conf»](zigbee.md#роли-и-stateconf)): `zigbee-coordinator.ybl` для
    `pulsar-coordinator`, `zigbee-router.ybl` для `router`. При роли `off` не прошивать.
- **`/tmp` — tmpfs** (размеры по моделям — [«RAM и tmpfs»](hardware.md#ram-и-tmpfs)): в конце
  сессии — `cleanup`.

## station.sh

Удалённые команды `tools/station.sh` выполняются на станции в busybox ash. Python-клиенты
`tools/esphome_check.py` и `tools/sendspin_server.py` ставят зависимости из `tools/requirements.txt`;
`tools/deconz_read.py` обходится стандартной библиотекой.
