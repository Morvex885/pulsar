# Радио Zigbee (Миди)

Справочник по радио Zigbee Станции Миди: железо, внешние прошивки и бутлоадер Яндекса, форматы
образов, карта flash, ключи `state.conf`, особенности стека и клиентов deCONZ. Здесь нет пересказа
кода: поведение кода — в коде, обоснования — в комментариях у кода. Пошаговая работа с радио —
skill `zigbee-radio`, правила для живых станций — [stations.md](stations.md), пункт «Радио Zigbee».

На Миди радио работает на собственной прошивке pulsar: это либо координатор сети с протоколом
deCONZ для Zigbee2MQTT / ZHA, либо роутер в чужой сети (например, Zigbee2MQTT). Где что лежит:

- `../satellite/crates/pulsar-zigbee/` — хост: сервис ролей, линк, координатор, сервер deCONZ,
  роутер, флешер. Карта крейта и внутренний API описаны в `//!` в
  [`lib.rs`](../satellite/crates/pulsar-zigbee/src/lib.rs).
- `../radio/` — прошивки pulsar на Telink Zigbee SDK (коммит закреплён в
  [`build.sh`](../radio/build.sh)), лицензия Apache-2.0 (см.
  [`common/board_cfg.h`](../radio/common/board_cfg.h)). Сборка — заголовок
  [`../radio/build.sh`](../radio/build.sh) (требования к системе) и
  [«Сборка»](development.md#сборка) (инструменты хоста).

## Радио Миди

- Чип Telink B91 (RISC-V) на `/dev/ttyS2`: 115200 8N1, без управления потоком.
- Линии reset и boot экспортирует драйвер ядра `zb_control`:
  `/sys/devices/platform/zigbee/zb-reset/value` (GPIOZ_11) и
  `/sys/devices/platform/zigbee/zb-boot/value` (GPIOZ_9). Обе линии active low: запись `1`
  активирует линию.
- Линии управляются только через эти файлы, никогда по номеру GPIO. `/etc/init.d/S30zigbee` из
  других сборок прошивки использует сырые номера, которые на этом ядре принадлежат другим пинам
  (475 = GPIOX_0, SDIO Wi-Fi).
- Измерено: после reset приложение присылает 0x8907 примерно через 0,3 с.

## Фрейминг zbhci

Фрейминг стоковый, Telink zbhci. Он одинаков у всех трёх прошивок: шлюзовой Яндекса, роутера и
координатора pulsar.

```
0x55 | type BE16 | len BE16 | xor(type, len, payload) | payload | 0xAA
```

- Прошивка принимает один фрейм на один DMA-буфер. Каждый фрейм подтверждается ACK 0x8000
  `[type BE16][status][0]`, статус 2 означает неизвестный тип. Следующий фрейм можно отправлять
  только после ACK.
- На ошибку разбора (start/end-байт, длина, xor) отвечает сам SDK (`stack/hci/uart/hci_uart.c`):
  он шлёт тот же 0x8000 со статусом ошибки. Если тип разобрать не удалось, в ACK стоит тип 0xFFFF.
- Все три прошивки отвечают на 0x0900 сообщением 0x8900
  `[version BE32][manufacturer BE16][image type BE16][size BE32]`. По этому ответу хост узнаёт,
  какая прошивка работает. Общие сообщения прошивок pulsar (0x8907, 0x0900, ACK) описаны в шапке
  [`radio/common/pulsar_hci.h`](../radio/common/pulsar_hci.h).

## Шлюзовая прошивка Яндекса

- С завода радио стоит на `gateway.ybl` из `/system/vendor/quasar/zigbee/`. Файл имеет формат
  `.ybl` (см. [«Образы .ybl и бутлоадер»](#образы-ybl-и-бутлоадер)): manufacturer 0x140A, image
  type 0x0580. На нём работает сеть, которую сформировал Яндекс, на канале 12.
- Ограничения этой прошивки: она не умеет читать и задавать сетевой ключ, PAN ID и extended PAN
  ID; APS-фреймы пропускает только для endpoint 1; ответы ZDO забирает себе. Поэтому pulsar её не
  использует.
- `ctl.sh disable` возвращает радио maind. maind заново записывает `gateway.ybl`, если версия из
  ответа на 0x0900 отличается от его файла. Версии образов pulsar не совпадают ни с одним
  `gateway.ybl`, так что после образа pulsar maind всегда возвращает свою прошивку.

## Образы .ybl и бутлоадер

- Формат `.ybl`: образ Telink в том виде, в каком его собрал линкер. Поле размера по смещению 0x18
  содержит длину без трейлера. За образом идёт трейлер — zlib CRC-32, LE. Упаковщик —
  [`radio/ybl.c`](../radio/ybl.c).
- Версия образа лежит в заголовке по смещению 0x02. Семейство прошивки определяется по
  `version >> 24`: 0x15 — шлюз Яндекса, 0x50 — роутер pulsar, 0x51 — координатор pulsar.
- Бутлоадер — «Yandex Bootloader v1.0.02». Он резидентный, занимает flash 0–0x7FFF и никогда не
  перезаписывается. Приложение слинковано на 0x20008000. Вход в бутлоадер:
  1. boot=1, reset=1, пауза 100 мс, reset=0, пауза 100 мс, boot=0.
  2. Отправить `\n`. В ответ приходит меню, которое заканчивается приглашением `BL > `.
  3. `1` — загрузка по XMODEM, `2` — запуск приложения.
- XMODEM: блоки по 128 байт. Если приёмник просит `C`, используется CRC-16, если NAK — контрольная
  сумма. Последний блок дополняется байтом 0x1A, затем нулями. В конце передачи — EOT.
- Это собственный путь обновления maind (`ncpmgr`). Флешер pulsar повторяет его.

## Карта NV

Flash радио — 1 МБ. Карта общая для трёх образов. Каждая прошивка хранит NV своей сети в своём
месте, поэтому при переключении образов сохраняются все сети. NV прошивок pulsar лежит внутри
области OTA-стейджинга шлюза: шлюз пишет туда, только когда его просит хост.

| область | адреса |
|---|---|
| бутлоадер Яндекса | 0x0–0x7FFF |
| приложение (последний записанный образ) | с 0x8000 |
| OTA-стейджинг шлюза | 0x77000–0xE5FFF |
| NV роутера | 0xC0000–0xD7FFF (счётчик factory reset 0xD6000, install code 0xD7000) |
| NV координатора | 0xA8000–0xBFFFF (0xBE000, 0xBF000) |
| NV шлюза | 0xE6000–0xFBFFF |
| калибровка | 0xFE000 |
| MAC/IEEE (общий для всех) | 0xFF000 |

Адреса заданы в [`radio/common/board_cfg.h`](../radio/common/board_cfg.h) и в
`radio/*/version_cfg.h`.

## Роли и state.conf

Ключи `state.conf` — контракт между версиями. Общий формат файла описан в
[«state.conf и откат на .prev»](architecture.md#stateconf-и-откат-на-prev).

- `zigbee_role=off|pulsar-coordinator|router`. Значение по умолчанию — `off`. Любое другое
  значение тоже читается как `off`, в том числе `coordinator` — роль шлюза Яндекса в старых
  сборках.

  | `zigbee_role` | прошивка | образ |
  |---|---|---|
  | `off` | радио не трогается | — |
  | `pulsar-coordinator` | координатор pulsar (0x51) | `/data/pulsar/zigbee-coordinator.ybl` |
  | `router` | роутер pulsar (0x50) | `/data/pulsar/zigbee-router.ybl` |

  Образы на станцию кладут установка и обновления. Имена ассетов описаны в
  [«CI и релизы»](development.md#ci-и-релизы), раскладка `/data/pulsar` — в
  [«Установка и станция»](development.md#установка-и-станция).
- `zigbee_flash_failed=<version hex>` — версия образа, который радио не приняло. Как pulsar
  учитывает этот ключ, описано в коде:
  [`service.rs`](../satellite/crates/pulsar-zigbee/src/service.rs), `decide`.

## Роутер

Роутер (семейство 0x50) — ретранслятор в чужой сети, например Zigbee2MQTT или ZHA. Команды zbhci
и события прошивки описаны в шапке [`radio/router/router.c`](../radio/router/router.c), сторона
хоста — в [`router.rs`](../satellite/crates/pulsar-zigbee/src/router.rs).

## Координатор

Координатор (семейство 0x51) работает как NCP: стек и trust center крутятся на чипе, а хост
выбирает сеть и получает каждый APS-фрейм. Команды — 0x0Axx / 0x8Axx, многобайтовые поля в них
little endian. Раскладки фреймов описаны только в шапке-комментарии
[`radio/coordinator/coordinator.c`](../radio/coordinator/coordinator.c), сторона хоста — в
[`coordinator.rs`](../satellite/crates/pulsar-zigbee/src/coordinator.rs). Порт сервера deCONZ
указан в [«Порты и тестовый режим»](architecture.md#порты-и-тестовый-режим).

## Стек libzb_coordinator.a

Стек поставляется готовой библиотекой `libzb_coordinator.a`, без исходников. Факты ниже проверены
по дизассемблеру — objdump из тулчейна Telink.

- Формирование сети берёт PAN ID из NIB (`NWK_NIB().panId`); 0xFFFF означает случайный. Если на
  канале слышен такой же PAN ID, стек уходит с него. `TL_ZB_ASSOCJOIN_PERMIT_PANID` стек
  игнорирует.
- `bdb_networkFormationStart` возвращает состояние BDB. Если формирование началось, это FORMATION.
- `zb_preConfigNwkKey` дополнительно помечает ключ как pre-configured
  (`ss_ib.preConfiguredKeyType` NWKKEY). После этого trust center никогда не передаёт ключ, и
  подключающиеся устройства бесконечно повторяют ассоциацию. Поэтому ключ задаётся через
  `ss_zdoNwkKeyConfigure` + `ss_zdoUseKey`.
- По умолчанию в BDB включён `tcRequireKeyExchange`. С ним сеть выбрасывает устройства Zigbee 1.2,
  которые никогда не обновляют link key. BDB восстанавливает это значение при каждой своей
  инициализации.
- Стирание (`zb_resetDevice2FN`) перезапускает счётчик APS и заново генерирует заводской IEEE. При
  загрузке стек восстанавливает из NV счётчик кадров, увеличенный на 1024.
- `af_dataCnfHandler` присылает подтверждения только для endpoint 0 и зарегистрированных endpoint.
- `rf_setChannel` также пишет `g_mac_pib->phyChannelCur`, а это значение стек сохраняет в NV.

## Клиенты deCONZ

Поведение внешних клиентов, под которое подстроен сервер deCONZ
([`deconz.rs`](../satellite/crates/pulsar-zigbee/src/deconz.rs)):

- zigpy-deconz (ZHA) при прошивке ConBee III 0x26780900 и протоколе 0x0106 сканирует энергию
  через ZDO к координатору. Команды update_neighbor, watchdog TTL и source routes он при этом не
  использует.
- Если хосту (zigpy, zigbee-herdsman) ответить «нет сети», он формирует новую сеть, а это стирает
  радио.
- zigbee-herdsman записывает endpoint 0xF2 в слот 1.
- zigbee-herdsman отправляет NWK_addr_req в режиме адресации NWK, но с IEEE-адресом. Поэтому
  payload на 6 байт длиннее заявленного.
