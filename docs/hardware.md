# Железо станций

Здесь факты о железе и прошивке станций: источники данных, C API библиотек Яндекса, таблица
моделей и заметки по отдельным моделям. Процедур и пересказа кода здесь нет: поведение кода — в
коде, обоснования — в комментариях у кода. Детект модели, выбор ABI, цепочка загрузки и раскладка
`/data/pulsar` описаны в [development.md, «Установка и станция»](development.md#установка-и-станция).

## Библиотеки Яндекса (C API)

Wake word, командный спотер и эхоподавление работают на проприетарных библиотеках прошивки.
Демон загружает их через `dlopen` во время работы, в репозиторий они не копируются
(AGENTS.md, «Git»). C API восстановлен реверсом `maind`, а сигнатуры, которые использует код,
лежат в [`../satellite/crates/pulsar-audio/src/engine/`](../satellite/crates/pulsar-audio/src/engine/).

`libyandex_evil.so` лежит в `/system/vendor/quasar/libs/` вместе с `libtflite.so` и
`libiconv.so`.

- VQE: `YandexVqeC_Config_CreateFromPreset(preset, &cfg)`,
  `YandexVqeC_Create(cfg, models_dir, 0, nullptr, &vqe)`,
  `YandexVqeC_Process(vqe, mics, nmic * chunk, spk, nspk * chunk)`. Сэмплы передаются как float в
  [-1, 1], с чередованием по кадрам. Размер входного чанка (`GetInputChunkSize`) и выходного кадра
  (`GetProcessingFrame`) задаёт пресет; значения по моделям — в строке «VQE» таблицы
  [«Модели»](#модели).
- `YandexVqeC_GetOutputChannelData(vqe, type, idx, &ptr, &n)` всегда возвращает «нет ошибки».
  Если выхода такого типа нет, функция отдаёт `n == 0`.
- `YandexVqeC_Config_GetOutputChannelCount` принимает `(cfg, type, int *out)`. Остальные геттеры
  `Config_Get*` возвращают значение напрямую.
- Спотер: `spotter_create_multichannel(conf, rate, n, types, false, &err)` и
  `spotter_submit_raw_data(sp, s16_interleaved, bytes, &err)`. Сколько каналов нужно каждому
  типу, задаёт конфиг модели спотера (`spotter_conf_get_required_channel_count`). Спотер типа 0
  получает основной канал VQE.
- События спотера (`event_id_to_str`): 2 и 5 — срабатывания (`CONFIRMATION_1ST_STAGE` и
  `_2ND_STAGE`), 3 — `1ST_STAGE_HIT` (верификатор ждёт ещё данных), 6 — отказ второй стадии.
  Спотер подтверждает слово через несколько чанков после того, как оно закончилось. По замеру
  `frontend_probe` от 2026-10-28 обе модели Лайт 2 и «Яндекс» на Миди события 3 не выдают
  (подтверждают событием 2), а у «Алисы» на Миди событие 3 приходит в одном чанке с 5. Как
  измерять пре-ролл, описано в
  [voice.md, «Пре-ролл: методика измерения»](voice.md#пре-ролл-методика-измерения).
- `libquasar_gstreamer.so` — GStreamer 1.14.5 из прошивки, тоже загружается через `dlopen`. При
  переходе PLAYING → PAUSED его alsasink делает `snd_pcm_drop`: на Миди каждая пауза съедала около
  200 мс ответа. С `sync=true` опоздавшие сэмплы отбрасываются. В сборке Миди нет экспорта ни
  appsink API, ни `gst_buffer_map`; `parse_launch`, `g_object_get` / `g_object_set` и
  `gst_bin_get_by_name` есть на всех моделях.

библиотеки Лайт 2 таких алиасов нет, и текущий ABI там под обычными именами.

## Заметки по моделям

Миди, замеры ALSA: dmix, который опустел и запустился заново, теряет ~60 мс следующих записанных
сэмплов, а `snd_pcm_delay` показывает на ~70 мс меньше, чем на самом деле осталось доиграть.

### Лайт 2: буфер захвата

Буфер PDM-захвата — не больше 2048 кадров (~42 мс при 8 каналах S16): чтение захвата вместе с VQE
в одном потоке его переполняет. Несколько переполнений в час (`capture: Broken pipe, recovering`)
остаются и при отдельном потоке чтения, это ожидаемо.

### Лайт 2: светодиоды

Trigger `led_ring_fb` масштабирует каждый канал по дороге к светодиодам. sysfs `brightness`
показывает значение из framebuffer, умноженное примерно на 0,36 (красный), 0,23 (зелёный) и 0,2
(синий), с потолком 63. Поэтому цвета кольца, проверенные через sysfs, совпадают с цветами Миди
только после этой поправки. В `/dev/fb0` лежат записанные байты B, G, R.

### Мини 2

Данные контрибьюторов, прошивка 0.369, если не сказано иное.

- Часы не горят только потому, что не проходит probe чипа часов
  (`register write to 0x4F failed (error -6)`). Узел DT в порядке, так что исправление прошивки
  или драйвера вернёт панель. На станции из #38 (прошивка 0.372) есть и панель (28 сегментов), и
  датчик освещённости `ltr308als01` (`in_intensity_input` = raw / 120, без
  `/etc/light-sensor.conf`). На станции из #9 (0.369) датчика нет [inference: чем станции
  отличаются (прошивкой, ревизией платы или device tree), неизвестно].
- Кнопка отключения микрофонов без фиксации, но схема микрофонов запоминает состояние: пока
  микрофоны отключены, GPIOZ_3 читается как 0 и держит этот уровень между нажатиями, так что
  уровень и есть состояние. GPIOZ_8 (419) только даёт импульс высокого уровня во время нажатия.
  Событий evdev кнопка не шлёт (`sar0_pad0` отдаёт только 582/115/114), а нажатие не обновляет
  `data/is_speaker_muted`, поэтому этот файл как состояние не годится.
- В GStreamer этой прошивки нет декодера MP3; стоковые earcons — в `.opus`
  (`common/volume_sound.opus` [inference: наличие файла на станции не подтверждено]).
- До порта на Rust на железе с C++-демоном из #9 проверено: загрузка пресета VQE и захват,
  wake word → конвейер HA → TTS, воспроизведение через 32-битный GStreamer прошивки на `default`,
  Sendspin с Music Assistant, кольцо, сенсорные кнопки, громкость, отключение микрофонов через
  GPIO и `pulsar-install` от начала до конца. Не проверено: часы, качество спотера, порт на Rust
  на станции.

### Зависший dmix lock

Зависший dmix lock (stale dmix lock): если процесс убит во время воспроизведения, все следующие
плееры молчат до перезагрузки, и перезапуск демона не помогает. Причина — dmix в alsa-lib
прошивки: shm-сегмент остаётся со счётчиком клиентов, который уже никто не уменьшит. Механизм
подробно описан в заголовке
[`../satellite/deploy/supervise.sh`](../satellite/deploy/supervise.sh); там он прописан для Миди и
Лайт 2.

Ключи IPC:

- `speakers` прошивки (Миди, Лайт 2; ключ у Мини 3 — в [mini3.md](mini3.md)):
  shm 0x400 (`ipc_key 1024`), 0x401 (буфер микширования), семафор 0x400;
- `minidmix` у Мини (`ipc_key 2277` в [`../satellite/deploy/asound.conf`](../satellite/deploy/asound.conf)):
  shm 0x8e5, 0x8e6, семафор 0x8e5;
- `dmix_spk_plug` у Мини 2: ключ не сверен.

Вручную lock снимают так: `ipcrm -M 0x400 -M 0x401 -S 0x400` (у Мини —
`ipcrm -M 0x8e5 -M 0x8e6 -S 0x8e5`), и только если `ipcs -m` показывает nattch 0 у обоих
сегментов.
