## Что обязательно сохранить

- **Сохранить — deCONZ:**
  - сокет: порт из конфига, backlog 2;
  - **подключения:**
    - клиент не принимается, пока радио не готово;
    - новый клиент вытесняет старого, увеличивается generation;
    - при рестарте радио вне формирования клиент рвётся;
  - **кадры:** SLIP с лимитом 1024 и checksum;
  - **команды и параметры:**
    - команды 0x04, 0x07, 0x08, 0x0A, 0x0B, 0x0D (0x26780900), 0x0E, 0x12, 0x17; на остальные ответа нет;
    - таблицы read/write parameter целиком;
    - статусы 1, 4, 7;
  - **очереди и слоты:**
    - очереди confirm/indication по 64 с вытеснением старых;
    - endpoint-слоты по умолчанию и `set_slot`;
  - **APS:** handle `generation<<8|req_id`; quirk herdsman (NWK-режим с IEEE → 0xFFFD);
  - **формирование:** `AWAIT_ERASED` → `FORMING`, `next_network()`, `form_channel()`, смена канала.
- **Сохранить — сервис:**
  - `bring_up`, 0x0900/0x8900, ожидание ответа 10 с, повтор через 60 с после FAILED;
  - таблица решений `on_firmware` (точная версия, семейство, `failed_version`, gateway 0x15);
  - не больше 2 прошивок за старт; `FlashOutcome`; прошивка в отдельном потоке с прогрессом шагами по 5 %;
  - всегда `bring_up` после прошивки; порядок `tear_down`;
  - тексты `status()` дословно.
- **Геттеры** (ARCHITECTURE «Модель исполнения» п.2):
  - `mode()` — константа из `spawn` (смена роли = рестарт демона);
  - `flashing()` ведёт актор: запись начинается по ответу радио или таймауту, а не по команде;
  - `status()` ведёт актор. Начальная фаза считается в `spawn` («off» / «starting» / «error: cannot open the radio», `service.cpp:58-89`), и первый `Changed` уже лежит в канале, когда `spawn` возвращается;
  - `join()`: актор проверяет условия C++ (фаза Running и роутер, затем `ready && !joined && !joining`), ставит `joining = true`, очищает `error`, шлёт kSteer, взводит таймер 90 с и отправляет `Changed` (как `router.cpp:66`);
  - `leave()`: актор при условиях C++ (Running, роутер, `ready`) ставит `joining = false` и очищает `error`, без `Changed` (как C++);
  - это намеренное отличие от C++ (ARCHITECTURE «Модель исполнения» п.2): C++ меняет `joining`/`error` синхронно в вызове (`router.cpp:50-51, 72-73`), а здесь флаги на стороне handle не заводятся вопреки общему правилу синхронности. Допустимо, потому что контроллер читает `status()` только по `Changed` и в `on_client_connected`; `ClientConnected` между `join()` и актором публикует прежний статус, и следующий `Changed` его исправляет.

## Проверка на станциях

- **Станции (Midi, `stop`):**
  - если роль `pulsar-coordinator`: `zigbee_probe 16639` и с машины агента только чтение: version 0x0D, device state 0x07, read parameter MAC/PAN/ext PAN/канал/NWK update id/protocol version. Скрипт или zigpy-deconz — **без** write parameter и без смены network state;
  - если роль `router` или `off` — проверка переносится в WP-12 (тестовый экземпляр: text sensor «Zigbee» с осмысленным статусом).
