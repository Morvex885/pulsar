## Что обязательно сохранить

- **Сохранить:**
  - поток GLib, команды через `g_idle_add`-трамплин (`Box<dyn FnOnce()>` → `gpointer`), события через `UnboundedSender`;
  - `playbin name=ch%d audio-sink="alsasink device=speakers"`, flags AUDIO|SOFT_VOLUME, `buffer-duration` 500 мс у ANNOUNCE;
  - регистрация статических плагинов (список `kPlugins`), `g_io_openssl_load`, `SSL_CERT_FILE`;
  - вариадический `g_object_set` с типами f64 / i64 / u32;
  - раскладки `GstMessage` с const-assert (aarch64: type@64, src@80; armhf: 36/48) и `GError`;
  - вся машина состояний: `advance`/`finish`/`halt`, буферизация, CLOCK_LOST, ретраи (только MUSIC, http(s), `soup_status`/quark, 3 попытки, `1000<<n` мс, сброс через 60 с, `resume_ns`), рампа gain 0.05 на 20 мс;
  - `Done` ровно один раз;
  - Mixer: `Master Playback Volume` на `hw:0`, создание через открытие `speakers`, кривые `to_raw`/`from_raw`/legacy 1:1 как свободные функции `pulsar_media::mixer::*`, mute = raw 0, деградированный режим без контрола (volume в памяти, 0.5 по умолчанию);
  - деградированный Player при неудачной инициализации: каждый `play()` → `Done{ok:false}` (`player.cpp:612-615`);
  - `pulsar_alsa::quiet_error_handler()` при старте плеера (`player.cpp:559-560`);
- **`PlayerHandle::state(ch)`** пишет только рабочий поток GLib (атомик), как в C++: команды уходят туда через `g_idle_add`, поэтому `play`/`pause`/`resume`/`stop` синхронно состояние не меняют, и сразу после команды геттер отдаёт прежнее значение — как C++. Ставить `Loading` в handle нельзя: в C++ пустой список URL даёт `Error` → `Idle`, а `pause`/`resume` неактивного канала ничего не делают. Атомик обновляется до отправки `State`; деградированный handle всегда отдаёт `Idle`. `Mixer` синхронный целиком.
