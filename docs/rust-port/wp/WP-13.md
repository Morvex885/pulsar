## Проверка на станциях

- **Регрессия на обеих станциях:** тестовый экземпляр, все сценарии `esphome_check.py`, все probe-утилиты. Отложенные проверки WP-09 и WP-10 закрыть или перенести в чек-лист владельца с причиной.
- **Креш-отчёт:** `kill -SEGV` тестового экземпляра → в логе строка формата `=== CRASH SIGSEGV addr=0x… pc=0x… lr=0x… handler=0x… ` (после `kill` pc и lr лежат в libc, это ожидаемо).
  - Non-PIE подтверждается так: значение `handler=` равно адресу из `nm build/<arch>/pulsar.debug | grep ' T pulsar_crash_handler$'` (на armhf есть ещё локальные `.Lswitch.table.pulsar_crash_handler*`).
  - На aarch64 есть строка `fp:`. Если хотя бы один адрес из неё резолвится `addr2line -f -e build/<arch>/pulsar.debug` в функцию — записать в отчёт. Если ни один — тоже записать, это не блокер.
- **Замер:**
  - живая подмена на 2 ч на каждой станции, lock на 150 минут;
  - RSS (`VmRSS`/`VmHWM`) и CPU простоя (дельта utime + stime из `/proc/<pid>/stat` за 60 с) у C++ (до подмены) и у Rust;
  - критерий для Lite 2: RSS ≤ 1.5× C++ и CPU простоя ≤ C++ + 3 п.п.; на Midi — только запись.
  - Превышение исправляется в этом пакете. Если исправить нельзя — владельцу сообщается с цифрами.

- **Чек-лист владельца** в PROGRESS.md: пункты, которых агент проверить не может (см. раздел «Чек-лист владельца» в PROGRESS.md; отложенные проверки WP-09, WP-10, WP-12 переносятся туда с причиной).
