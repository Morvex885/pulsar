## Что обязательно сохранить

- **Сохранить:**
  - API 1.15; ESPHome version `2026.9.0`; project `pulsar.satellite`;
  - лимиты (1 MiB кадр, 256 KiB аудио-backlog, 8 MiB backlog, 64 KiB чтения на пробуждение, 4 клиента, 4 pending, hello 15 с, ping 45 с, drop 100 с, GetTime каждые 6 ч);
  - выбор протокола по первому байту;
  - Noise: `Noise_NNpsk0_25519_ChaChaPoly_SHA256` через `snow` в роли responder; prologue `"NoiseAPIInit" + BE16(len) + client hello`; ответ сервера `[0x01][name]\0[mac lower hex]\0`; reject-кадры `0x01 + текст` с теми же текстами (`Handshake MAC failure`, `Handshake error`, `Bad handshake packet len`, `Bad indicator byte`, `Empty handshake message`, `Bad handshake error byte`); данные `[type BE16][len BE16][msg]`, лимит 0xFFFF;
  - ключ: base64 32 байта, нулевой ключ = нет ключа; без ключа принимаются и plaintext, и Noise с нулевым PSK (путь provisioning ESPHome, `api_server.cpp:505-534`, лог `provisioning key`); fail-closed на битом файле (случайный ключ через `libc::getrandom`); атомарная запись `.tmp` 0600 + `\n`; после `set_key` через 100 мс перезагрузка ключа, `MdnsTxtChanged(mdns_txt())` и разрыв всех клиентов;
  - TXT `_esphomelib._tcp` в порядке C++ (`api_server.cpp:485-501`);
  - голосовой run id: `voice_request_start` возвращает новый id, `VoiceStartFailed` и `VoiceAudioOverflow` несут id run, во время которого случились;
  - TCP-опции через `socket2`: NODELAY, keepalive 20/5/3, `TCP_USER_TIMEOUT` 30000; backlog 4, SO_REUSEADDR;
  - voice-владелец: `voice_wanted = ++seq`, передача с `VoiceSubscribed(false)` перед `(true)`, ранжирование `make_room`;
  - переполнение аудио-backlog: `VoiceAssistantRequest(start=false)` + `VoiceAudioOverflow`, дальше аудио отбрасывается до следующего start;
  - лог-sink через `pulsar_core::set_log_sink` + `Notify`, уровни ESPHome {5,3,2,1}.
- **Геттеры `connected()`/`voice_subscribed()` — намеренное отличие от C++** (ARCHITECTURE «Модель исполнения» п.2). В C++ ошибка записи или переполнение backlog («client not reading»: `send_msg` → `flush` → `close_client`) синхронно закрывали клиента внутри `voice_request_start`, `voice_request_stop`, `voice_send_audio`, `voice_announce_finished` и `publish_*`. В Rust ввод-вывод делает актор: сразу после вызова геттер отдаёт прежнее значение, итог приходит только событиями `VoiceStartFailed{run}`, `VoiceAudioOverflow{run}`, `VoiceSubscribed(false)` и, возможно, `VoiceSubscribed(true)` (`close_client` → `update_voice_owner` передаёт голос другому клиенту), `ClientDisconnected`; актор обновляет геттеры до отправки события. `mdns_txt()` считается в `spawn` (`load_key`), после `set_key` + 100 мс актор пересчитывает его до `MdnsTxtChanged`.

## Host-тесты (обязательные)

- **Host-тесты:**
  - golden-векторы proto (varint, sint, fixed, float, packed, Reader на битом вводе);
  - разбор plaintext-кадров, включая усечённые и слишком большие;
  - полный Noise-handshake и обмен данными с инициатором на `snow` в тесте, в том числе неверный PSK → reject `Handshake MAC failure`;
  - `load_key` для всех случаев (нет файла, пустой, нулевой, битый → fail-closed, валидный);
  - выбор voice-владельца и ранжирование вытеснения;
  - переполнение backlog → событие и стоп.
  - Акторные тесты — на `LocalSet` с реальным TCP на 127.0.0.1.
