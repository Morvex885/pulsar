## Что обязательно сохранить

- **Сохранить** — всё поведение `controller.cpp` 1:1:
  - **константы и пути;**
  - **`state.conf`:** формат, ключи, значения по умолчанию, порядок записи, атомарная запись, миграция `volume`/`volume2`/`volume_curve`, `update_attempt` при старте, `led_case_color`. Числа с плавающей точкой пишутся через `pulsar_core::fmt::g6` (как C++ ostream, 6 значащих цифр), читаются через `parse_f32_prefix` (как `strtof`). Булевы — `0`/`1`. `zigbee_flash_failed` — hex в нижнем регистре без `0x` (`controller.cpp:118-127`);
  - **деградированные сервисы:** Player, Leds, Clock, AudioFrontend, Mixer всегда есть (см. ARCHITECTURE.md). `None` бывают только Sendspin, Input, LightSensor, mDNS. ApiServer → код 1;
  - **остановка фронтенда:** drop последнего `FrontendHandle` останавливает и join-ит потоки захвата и обработки на потоке рантайма (до ~200 мс `snd_pcm_wait` плюс обработка текущего чанка); это время входит в `shutdown_timeout`/watchdog teardown;
  - **голосовой run:** id из `voice_request_start`; `VoiceStartFailed`/`VoiceAudioOverflow` с чужим id игнорируются;
  - **TZ;**
  - **identity:** `host_prefix` + 6 последних hex MAC wlan0 в нижнем регистре; MAC в верхнем; manufacturer `Yandex`; board = codename; compilation_time;
  - **`ApiConfig`:** списки из `pulsar_hw`, `pulsar_clock`, `pulsar_zigbee::ROLES`; слова `alisa`/«Алиса» и `yandex`/«Яндекс»;
  - **порядок запуска** (ошибка `pulsar_esphome::spawn` → код 1; неудачный Sendspin → без него);
  - **mDNS при offset 0:**
    - создаётся респондер с `_esphomelib._tcp` (TXT из `api.mdns_txt()`);
    - добавляются `_sendspin._tcp` (`path=/sendspin`, `name=<friendly>`) и `_zigbee-coordinator._tcp` (только в роли coordinator);
    - `MdnsTxtChanged` → `set_txt`;
  - **голосовой автомат:**
    - фазы, watchdog 30/120 с, привязка событий к run;
    - арбитраж по `claim_id`, буфер аудио и команды на время арбитража;
    - `ArbiterHandle::cancel()` не отзывает уже поставленный в очередь `Decided` (без сокета он ставится в очередь прямо в `claim()`): при отмене контроллер забывает `claim_id`, а `Decided` с чужим или забытым id игнорирует;
    - барж-ин, earcon'ы, `continue_conversation`;
  - **анонсы:**
    - HA-анонсы с `voice_announce_finished` ровно один раз;
    - media-анонсы без него;
  - **HA-таймеры:** выбор показываемого; звонок до 15 мин; уступка речи;
  - **звук и команды:**
    - ducking 0.15;
    - гейтинг командного спотера (2.5 с после wake, 2600 мс таймер);
    - локальные команды и блокировка на 2.5 с после проигранного арбитража;
    - кнопки; mute;
  - **медиа:** медиа-команды, Sendspin-хуки;
  - **лампа и lux:**
    - `led_show` с разбором `#RRGGBB`;
    - троттлинг lux (первое значение, |Δ| > max(1, 10 %), 60 с);
  - **обновления:**
    - проверка через 60 с, затем каждые 6 ч;
    - авто-установка только в простое, повтор через 10 мин;
    - `/proc/self/exe` без ` (deleted)`;
    - остановка через 500 мс после успеха;
  - **отказы при прошивке радио:** отказ рестарта и установки, пока радио прошивается;
  - **порты:** `PULSAR_PORT_OFFSET`.
- **Порядок чтения геттеров — как в C++** (ARCHITECTURE «Модель исполнения» п.2):
  - `music_pause()` решает по `PlayerHandle::state(Music)` и `SendspinHandle::streaming()`, прочитанным до команд `pause`/`transport(Pause)`, и возвращает, играло ли что-то. Синхронного обновления состояния плеера в handle нет (в C++ его тоже нет), поэтому результат совпадает с C++;
  - `publish_media`/`update_commands`/`update_music` сразу после команды плееру видят прежнее состояние, как C++. Новое приходит событием `PlayerEvent::State`, и по нему контроллер вызывает `publish_media()`, как хук `on_state` в C++;
  - результат отправки голосового запроса берётся только из событий (`VoiceStartFailed{run}`), а не из `voice_subscribed()` сразу после вызова;
  - обновления: контроллер обрабатывает каждое `Checked`/`Installed` (колбэки C++ не несут seq). `install_update` отказывает при `busy()` и пока есть ожидающая проверка (сохранённый `Some(id)`, чей `Checked` ещё не обработан) — так повторяется C++ `busy()` (`controller.cpp:1132`), который оставался `true` до колбэка проверки; иначе в окне «`busy()` уже `false`, `Checked` в очереди» HA INSTALL поставил бы старый `release_`. Проверки делаются до изменения своего состояния. `None` от `check()`/`install()` не перезаписывает сохранённый id. Для `Installed` окно закрывает `update_installing_`;
  - выход во время установки (`install()` вернул `Some(id)`, а `Installed` для этого id ещё не пришёл): перед выходом контроллер стирает `update_attempt` из `state.conf`. Причина: Rust-updater при закрытии handle отменяет установку до `--version` и замены (бинарь не меняется), а C++ доводил её до конца; оставшийся `update_attempt` заставил бы автообновление пропускать этот тег (AGENTS.md «Updates from HA»);
  - Zigbee: `status()` читается только по `ZigbeeEvent::Changed` и при подключении клиента HA (как C++: хук `controller.cpp:895-901` и `on_client_connected`, `controller.cpp:363`); сразу после `join()`/`leave()` его не читают. Обработка `Changed` дедуплицирует по последнему опубликованному статусу (`zigbee_status_`) и пишет в лог «zigbee: …», как хук C++; публикация в `on_client_connected` этот кэш не трогает;
  - `ApiHandle::{connected, voice_subscribed}` сразу после вызова не говорят о результате отправки (намеренное отличие от C++); результат — только события.
  - `PlayerEvent::Done`: список, закончившийся на потоке GLib до `stop()`/`play()`, получает `ok` по факту (в C++ — `false`), поэтому `voice_announce_finished(ok)`/`tts_finished(ok)` могут увидеть `true` там, где C++ давал `false`. Контроллер, как и в C++, сначала проверяет, что `PlayId` принадлежит текущему диалогу/анонсу (`dialog_`, `announce_seq_`); устаревший id игнорируется.
- **Порядок запуска:** `pulsar_media::spawn()` вызывается раньше, чем стартует любой другой сервис со своим потоком (`pulsar_audio::spawn`, Sendspin и т. д.): `spawn` ставит `SSL_CERT_FILE` через `std::env::set_var`, и в этот момент никакой C-код не должен читать окружение из другого потока.

## Проверка на станциях

- **Станции (обе):**
  - **Тестовый экземпляр** (`stop`, `PULSAR_PORT_OFFSET=10000`):
    - все `esphome_check.py` сценарии;
    - во время `scenario-voice` и `scenario-timer` — readback LED и часов (состояния LISTENING/THINKING/SPEAKING/TIMER_RING видны в sysfs, таймер на часах);
    - звук ≤ 0.2;
    - Sendspin на 18928 через `sendspin_server.py`, если он есть;
    - Midi: text sensor «Zigbee» соответствует роли.
  - **Живая подмена** `swap-rust` на ≥ 15 минут на каждой (lock на ≥ 30 минут):
    - в логе `Home Assistant connected`, нет `=== CRASH`, `=== exit` и `=== supervise`;
    - затем `restore-cxx`;
    - на Midi в роли `pulsar-coordinator` — только при условиях из STATIONS.md: совпадение `deconz_read.py` у тестового экземпляра и эталонного C++ `zigbee_probe`, плюс подтверждение владельцем свежего бэкапа Z2M/ZHA. Иначе подмена на Midi пропускается, пункт уходит в чек-лист владельца.
