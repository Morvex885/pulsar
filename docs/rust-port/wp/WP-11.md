## Крейт и модули

- **Крейт `pulsar-update`**, модули `https`, `version`, `updater`.
  - `https`: `TcpStream` + `tokio-rustls`, `RootCertStore` из PEM-бандла через `rustls-pki-types`; путь к корням — параметр, в проде `/etc/ssl/certs/ca-certificates.crt`.
  - `updater`: актор. Файловые операции через `tokio::fs` или `spawn_blocking`, `--version` через `tokio::process::Command` с таймаутом 10 с.
  - sha256 — `ring::digest`.

## Что обязательно сохранить

- **Сохранить:**
  - **URL и соединение:** только https; порт 443 по умолчанию; connect 10 с, I/O 20 с; TLS ≥ 1.2, SNI, проверка имени;
  - **запрос:** заголовки (`Host`, `Connection: close`, `Accept-Encoding: identity`, `User-Agent: pulsar/<ver>`);
  - **ответ:** лимит заголовков 64 KiB; правила редиректов (относительный Location); chunked; `response too large`; без длины — чтение до закрытия; прогресс; отмена; тексты ошибок;
  - **check:** `releases/latest` с `max_redirects=0` → тег из Location, `safe_tag`, URL ассетов `pulsar-<arch>.bin` и `SHA256SUMS`;
  - **install:**
    1. скачивание, проверка размера 64 MiB / 1 MiB;
    2. разбор SHA256SUMS;
    3. `pulsar.new` 0755 + fsync;
    4. точная первая строка `pulsar <tag>`;
    5. extras: 404 пропуск, несовпадение — fatal;
    6. `.prev` через `pulsar.prev.tmp`;
    7. переименования, `sync()`;
  - **ошибки и прогресс:** флаги fatal; формула прогресса `got*95/total`;
  - `release_newer` — правила C++.
- **`check()`/`install()` и `busy()`** (ARCHITECTURE «Модель исполнения» п.2):
  - возвращают `Option<u64>`: `None` = busy, запрос не принят, события не будет (C++ молча возвращался, `updater.cpp:181, 214`); `Some(id)` — id из одного общего счётчика с 1, только для связи ответа с запросом (в C++ не отменяется);
  - `busy` ставит CAS в handle до отправки команды. Поле существует в одном экземпляре, актор не держит копию. Актор сбрасывает его непосредственно перед отправкой `Checked`/`Installed` (в C++ `busy_ = false` выполнялось перед `done`, `updater.cpp:205-206, 317-318`);
  - окно: `busy()` уже `false`, пока событие ещё в очереди. Для `Installed` его закрывает `update_installing_` контроллера; для `Checked` — контроллер, который не начинает установку, пока id проверки не обработан (WP-12). Так повторяется C++, где `busy()` оставался `true` до колбэка проверки.

Примечание о `make check` и `ring`: кросс-clippy в `make check` (`cargo clippy … --target aarch64-unknown-linux-gnu --target armv7-unknown-linux-gnueabihf`) идёт без C-компилятора для целей. Если build-скрипт `ring` под ним падает, заменить эту строку Makefile на проверенную в WP-00 форму (cargo-zigbuild 0.24.0 поддерживает подкоманду `clippy`):

```
CARGO_ZIGBUILD_ZIG_PATH=<абсолютный путь zig> CARGO_ZIGBUILD_PYTHON_PATH=/nonexistent/python3 \
  cargo-zigbuild clippy --workspace --all-targets --locked \
  --target aarch64-unknown-linux-gnu.2.36 --target armv7-unknown-linux-gnueabihf.2.30 -- -D warnings
```

(или другой способ, проверенный на деле), и тогда job `check` в CI получает zig 0.14.1 (`mlugg/setup-zig`) и cargo-zigbuild 0.24.0, как job `build`.
