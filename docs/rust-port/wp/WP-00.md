### Cargo workspace и сборка

- `satellite/Cargo.toml`, `satellite/rust-toolchain.toml`, `[workspace.dependencies]` и `[profile.release]` — как в разделе «Workspace». `Cargo.lock` коммитится.
- `satellite/Makefile` переписывается целиком. Сохраняется контракт: `make -C satellite` собирает оба arch, выход — `build/<arch>/pulsar` и `build/<arch>/pulsar.debug`. От этого контракта зависят installer (`deploy.go` вызывает `make -C <root>/satellite -j`), `dist.sh` и CI.
  - Переменные по arch:

    | ARCH | TARGET | CPU | RUST_TARGET | GLIBC |
    |---|---|---|---|---|
    | aarch64 | `aarch64-linux-gnu.2.36` | (пусто) | `aarch64-unknown-linux-gnu` | 2.36 |
    | armhf | `arm-linux-gnueabihf.2.30` | `-mcpu=cortex_a53` | `armv7-unknown-linux-gnueabihf` | 2.30 |

  - Остаётся проверка версии zig (отвергать 0.11–0.13) и правила sendspin-cpp без изменений: `SS_STAMP`, `fetch.sh`, `CMakeLists.txt`, `toolchain/zig.cmake`, cmake + ninja в `build/<arch>/third_party`.
  - Удаляются правила C++-компиляции (`SRCS`/`OBJS`/`CXXFLAGS`/`LDFLAGS`) и sysroot. Удаляется файл `third_party/sysroot.sh`.
  - `VERSION := $(shell git describe --tags --match 'v*' --always --dirty 2>/dev/null || echo unknown)`. `--match 'v*'` — отступление от исходного плана, решение владельца: иначе ближайшим тегом на ветке `rust` оказывается `rust-port-base`, версия выглядит как `rust-port-base-N-g<hash>`, и updater не может её разобрать.
  - `BUILD_TIME := $(shell TZ=UTC0 LC_ALL=C git log -1 --format=%cd --date=format-local:'%b %e %Y, %H:%M:%S' 2>/dev/null || echo unknown)` — дата коммита HEAD в формате C++ `__DATE__ ", " __TIME__`. Используется не `date`: cargo отслеживает переменные, прочитанные через `option_env!`, и иначе крейт `pulsar` пересобирался бы с thin LTO при каждом `make`, в том числе при каждом деплое installer'а.
  - Окружение cargo для arch-сборок. C/C++ из build.rs (ring, шим Sendspin) компилируют обёртки cargo-zigbuild. Поэтому `CC_*`/`CXX_*`/`ZIG_TARGET`/`ZIG_CPU` в окружение cargo **не** задаются: `cc` добавляет `--target=<llvm triple>`, а `third_party/toolchain/zig-c++` его не фильтрует. `zig-cc`/`zig-c++` остаются только для CMake-сборки sendspin-cpp.
    ```
    PULSAR_VERSION='$(VERSION)' PULSAR_BUILD_TIME='$(BUILD_TIME)'
    PULSAR_SS_SRC=$(CURDIR)/third_party/src PULSAR_SS_BUILD=$(CURDIR)/build/$(ARCH)/third_party PULSAR_REQUIRE_SS=1
    RUSTFLAGS='-C relocation-model=static -C force-frame-pointers=yes'
    CARGO_ZIGBUILD_ZIG_PATH=<абсолютный путь $(ZIG)> CARGO_ZIGBUILD_PYTHON_PATH=/nonexistent/python3
    ```
    `CARGO_ZIGBUILD_*`: cargo-zigbuild иначе предпочёл бы `python3 -m ziglang` (любой версии) zig'у из `ZIG=`. Если `command -v $(ZIG)` пусто — `$(error …)`.
  - Первая цель в ветке с ARCH — `binary` (цель по умолчанию, `make ARCH=armhf` работает как раньше). Она зависит от `SS_STAMP` и делает `cargo zigbuild --release --locked -p pulsar --bin pulsar --target $(RUST_TARGET).$(GLIBC)`, затем `cp target/$(RUST_TARGET)/release/pulsar build/$(ARCH)/pulsar.debug` и `$(ZIG) objcopy --strip-all build/$(ARCH)/pulsar.debug build/$(ARCH)/pulsar`.
  - Цель `tools` (тоже зависит от `SS_STAMP`): `TOOLS := $(basename $(notdir $(wildcard crates/*/src/bin/*.rs)))`, `cargo zigbuild --release --locked --workspace --exclude pulsar --bins --target $(RUST_TARGET).$(GLIBC)` (без `pulsar`: `make binary tools` копирует его вне lock'а cargo). Каждый бинарь копируется в `build/$(ARCH)/tools/<имя>` уже стрипнутым (`$(ZIG) objcopy --strip-all`).
  - Шаблонное правило `build/$(ARCH)/tools/%` (зависит от `SS_STAMP`, `FORCE`): `cargo zigbuild … --bin $*` и та же копия со strip. Так продолжает работать документированное `make -C satellite ARCH=armhf build/armhf/tools/ww_offline`.
  - Цели `binary`, `tools` и шаблонное правило выполняют `cargo` всегда (`FORCE`). Инкрементальность обеспечивает cargo.
  - Без ARCH:
    - `all` → `aarch64 armhf` → `make ARCH=x binary`. Installer по-прежнему получает только бинарь.
    - `check` (host): `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, тот же clippy с `--target aarch64-unknown-linux-gnu --target armv7-unknown-linux-gnueabihf`, `cargo test --workspace --locked`, без переменных `PULSAR_SS_*`.
    - `clean`: `rm -rf build target`. `distclean`: ещё и `third_party/src`.

### Крейт `pulsar` (main)

Порт `satellite/src/main.cpp` без контроллера.
- CLI: `pulsar [--version | state_file]`. `--version` печатает `pulsar <PULSAR_VERSION>\n` и выходит с кодом 0. Версия берётся как `option_env!("PULSAR_VERSION").unwrap_or("unknown")` в `crates/pulsar/src/version.rs`, там же `BUILD_TIME` из `PULSAR_BUILD_TIME`.
- Путь состояния по умолчанию — `/data/pulsar/state.conf`.
- `crash.rs`: обработчик `#[unsafe(no_mangle)] pub extern "C" fn pulsar_crash_handler(sig, info, ctx)` — имя фиксированное, чтобы найти его через `nm`. Сигналы SEGV, BUS, ABRT, FPE, ILL. Флаги `SA_SIGINFO|SA_ONSTACK|SA_RESETHAND|SA_NODEFER`, sigaltstack 64 KiB, `alarm(3)`. Через `libc::write(2, …)` без аллокаций пишется ровно формат C++ (main.cpp:38–125). Каждое hex-поле, как `put_hex`, заканчивается пробелом:
  - `\n=== CRASH <SIGSEGV |SIGBUS |SIGABRT |signal >addr=0x… `;
  - на aarch64 `pc=0x… lr=0x… ` из `uc_mcontext.pc`/`regs[30]`;
  - на arm `arm_pc`/`arm_lr`. На прочих архитектурах (host x86_64 для `cargo test`/`clippy`) регистры не печатаются, остаются `addr` и `handler`; код регистров под `#[cfg(target_arch)]`;
  - `handler=0x… \n` (адрес `pulsar_crash_handler`, пробел перед переводом строки как в C++);
  - на aarch64 строка `fp: 0x… …` — проход по цепочке frame pointer (`regs[29]`, до 40 кадров, остановка на невыравненном, нулевом или неубывающем адресе). glibc `backtrace()` не используется: это решение для Rust, строка `bt:` не выводится.
  - Затем `SIG_DFL` и `raise`.
  - `panic = "abort"` даёт SIGABRT, и обработчик срабатывает. Стандартный panic hook печатает сообщение паники в stderr до abort.
- Порядок запуска:
  1. `init_logger()`.
  2. Обработчик крашей.
  3. `detect_model()`. `None` → код выхода 1.
  4. Рантайм current_thread + LocalSet.
  5. `tokio::signal::unix` SIGTERM/SIGINT → лог `signal N, exiting`.
  6. Лог `pulsar <ver> running on <model_name> (<codename>)`.
  7. Ожидание сигнала. Контроллер подключит WP-12.
  8. Затем watchdog teardown: поток, `sleep(5 s)`, `teardown did not finish in 5 s, _exit\n`, `libc::_exit(status)`.
  9. `actors::join_all(3 s)`, затем `runtime.shutdown_timeout(1 s)`, выход с кодом 0.
- SIGPIPE уже игнорируется Rust std.
