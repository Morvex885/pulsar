# Отчёты ревью

Каждый пакет перед влитием ревьюят минимум два независимых агента-ревьюера (правила — PROCESS.md, п. 7). Отчёт хранится в `docs/rust-port/reviews/WP-XX.md` и коммитится вместе с пакетом.

## Формат отчёта `WP-XX.md`

```
# Ревью WP-XX — <название пакета>

- Пакет: WP-XX
- Коммит-база: <sha origin/rust, от которого считался diff>
- Ревьюеры: A (баги и паритет с C++), B (архитектура, контракты, unsafe/FFI, конкурентность, ресурсы) [, C (unsafe) для WP-04/05/06]

## Блокирующие
- [блокирующее] файл:строка — проблема — почему — как исправить — статус (исправлено в <sha> / отказ: обоснование)

## Важные
- [важное] файл:строка — … — статус

## Мелкие
- [мелкое] файл:строка — … — статус

## Вердикт
- Ревьюер A: можно вливать | нельзя вливать (раунд N)
- Ревьюер B: можно вливать | нельзя вливать (раунд N)

## Проверка на станциях
Станция (Midi/Lite 2), дата, команда → ключевые строки вывода. Без реальных IP, MAC, серийников и адресов.
```

Правила:

- Каждое замечание в формате `[блокирующее|важное|мелкое] файл:строка — проблема — почему — как исправить`.
- Блокирующие и важные замечания исправляются либо письменно обосновывается отказ; после исправлений ревьюеры смотрят дельту, раунды перечисляются в «Вердикт».
- Пакет вливается, когда у всех ревьюеров последний вердикт — «можно вливать».
- Исправления чужих влитых крейтов (PROCESS.md, п. 3) описываются в этом же отчёте.
- Новая внешняя зависимость в `[workspace.dependencies]` обосновывается в отчёте.
- В разделе «Проверка на станциях» — команды и ключевые строки вывода (STATIONS.md, PROCESS.md, п. 6).
