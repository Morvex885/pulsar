## Важные

- [важное] проверка на станциях, Lite 2 (A) — `hw_probe light 10` не показал lux > 0 при освещении, как требует спека (`wp/WP-08.md`): во время проверки в комнате было темно — без подтверждения под светом пункт спеки не закрыт — повторить под светом — статус: принято как отклонение. У агента нет физической возможности осветить датчик. Read-only проверка sysfs (без lock, демон не останавливался) показала `in_intensity_raw=0`, `in_intensity_offset=0`, `in_intensity_scale=0.220897`, `in_intensity_input=0.000000` (5 чтений). Формула C++ даёт 0, а единичное значение 0.22 из hw_probe = raw 1 × 0.220897. Живой C++-демон в те же часы тоже видел 0.00–0.44 лк (днём 201.46 лк). На Midi lux > 0. Пункт «Датчик света Lite 2 под освещением» добавлен в чек-лист владельца (PROGRESS.md).

## Мелкие

Ревьюер A — замечания 2–7, ревьюер B — замечания 1–5. Все исправлены в итоговом коммите:
- [мелкое] `crates/pulsar-clock/src/light_sensor.rs` — опрос через `tokio::time::interval_at` с `period.max(1)` расходился с C++ при периоде 0 (в C++ это однократный таймер) — исправлено: `pulsar_core::Timers::set_repeating` в `select!` с `biased;` и `tx.closed()`, комментарий поправлен.
- [мелкое] `crates/pulsar-clock/src/sys.rs` — результат `localtime_r` не проверялся на null — исправлено: при null показывается 00:00 (нулевой `tm`), как в `pulsar-core`.
- [мелкое] `crates/pulsar-clock/src/clock.rs` (спад метров) — `f32::max` игнорирует NaN иначе, чем `std::max(in, shown·k)` — исправлено: семантика C++ (`in < decayed ? decayed : in`).
- [мелкое] `crates/pulsar-hw/src/bin/hw_probe.rs` — цикл мониторинга ввода/датчика не завершался, когда оба источника закрыты (у WP-07 был ранний выход) — исправлено.
- [мелкое] `hw_probe.rs` `expect_time` — при заданном TZ проверка UTC-часа ложно падала — исправлено: при TZ сравниваются только минуты, с пометкой в выводе.
- [мелкое] `hw_probe.rs` — число 42 (показ 1.5 с) проверялось на 3/4 слота, ровно на границе — исправлено: проверка на 1/2 слота; в usage указано `state_ms >= 2000`.
- [мелкое] `hw_probe.rs` `all` — не было строки C++ `open: leds= clock= input= light= hw_muted=` — исправлено (handle не сообщает об открытии; для LED и часов проверяется наличие fb/sysfs, датчик открывается в начале, как в C++).
- [мелкое] `light_sensor.rs` `parse_prefix` — в комментарии не сказано, что inf/nan/hex не разбираются — исправлено.
- [мелкое] `ARCHITECTURE.md` «Плавающая точка и паритет» — строка про `cortex-a53` дублировала «Рецепт линковки C++», пример armv7 (host-clippy) некорректен (clippy не исполняет код), не было правила о входах harness — исправлено: ссылка на рецепт, пример — ручной `cargo build --target armv7-…` без `RUSTFLAGS`, добавлено правило читать входы golden-harness во время выполнения (иначе clang сворачивает `log10f` и др. при компиляции).

## Исправление влитого крейта `pulsar-core` (PROCESS.md, п. 3)

- `crates/pulsar-core/src/ambient.rs` — `AmbientDimmer::update`: станционные C++-сборки (`zig c++ -O2`, clang `-ffp-contract=on`; aarch64 и armhf `-mcpu=cortex_a53`) сливают `0.02f + 0.98f*min(1,a)` и `smooth_ + 0.3f*(target - smooth_)` в FMA (`fmadd` / `vfma.f32` в asm `Clock::set_ambient_lux` и `Leds::set_ambient_lux` из `rust-port-base`); разность для гистерезиса не сливается. Rust-версия без FMA давала фактор на 1–2 ulp иначе. Исправлено: `mul_add` ровно в этих двух местах; тест `rounds_like_the_fused_cxx_build` (ожидаемые биты из C++ с FMA; со старым кодом тест падает). Оба ревьюера сверили исправление с C++-harness — подтверждено.
- Общее правило вынесено в ARCHITECTURE.md, раздел «Плавающая точка и паритет»; то же применено в `clock_fx` (интерполяция ключей, звонок) и к спаду диапазонов музыкальных уровней.

## Проверка на станциях

Выполнена 2026-10-24 на обеих станциях, `hw_probe` из ветки `wp/WP-08` (сборка `make … ARCH=aarch64|armhf binary tools`), сервис остановлен: `station.sh <st> lock 40` → `stop` → `push build/<arch>/tools/hw_probe` → запуски → `start` → `cleanup` → `unlock`. Перед захватом — `status` (Lite 2 занимали WP-03, затем WP-06; дождались освобождения).

Midi (aarch64):
- `hw_probe clock` → rc=0; все проверки `ok`: `check time (UTC): [16 34] ok`, `check level 255: current [255, 255] ok`, `check 42: [   42] ok`, `check level 5: current [5, 5] ok`, `check level 34: current [34, 34] ok`, `check level 100: current [100, 100] ok`, `check dark: [     ] ok` (обновление, выключение), `check 1234: [12 34] ok`, `check Smiley: [-? ?-] ok`, `check code: [12 3-] ok`; `final clock [16:35] current=100/100`, `restored clock current 89/89`.
- `hw_probe light 10` → rc=0, `lux 0.75` … `lux 1.12`.
- `hw_probe all 5` → rc=0: LED-проверки PASS, проверки часов как выше, `lux 4.12` … `lux 6.75`, `== exit (actors stopped: true)`, кольцо и логотип погашены (PASS), `restored clock current 89/89`.

Lite 2 (armhf):
- `hw_probe clock` → rc=0; все проверки `ok`, уровень по значению горящих сегментов: `check level 255/5/34/100: lit segments [255…]/[5…]/[34…]/[100…] ok`, время, 42, текст `[12 34]`, лицо, код `[12 3-]`, темно при обновлении и выключении.
