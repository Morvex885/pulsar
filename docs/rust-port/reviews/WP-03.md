- Пакет: WP-03
- Коммит-база: `origin/rust` на момент захвата (`69e3794`, коммит захвата WP-03)

## Блокирующие

## Важные

- [важное] `crates/pulsar-lan/src/arbiter.rs` (B; A — мелкое) — в `select!` таймеры стоят раньше сокета. Claim пира, уже лежащий в сокете к моменту решения, не учитывался, а tokio мог ещё не увидеть готовность. В C++ цикл обслуживал fd раньше таймеров — исправлено в `6f183ed`: перед каждым таймером (досылка копии, решение) сокет вычерпывается обычным `recv`, не больше 64 датаграмм, каждая через `on_datagram`. Тест Rig: датаграмма записана в сокет актора по loopback, без вызова `on_datagram`, и после окна она учтена в `peers`.
- [важное] `arbiter.rs` `cancel`, ARCHITECTURE `pulsar-lan` (B; A — мелкое) — документация обещала, что после `cancel()` `Decided` не придёт. На деле уже поставленный в очередь `Decided` придёт, а без сокета его ставит в очередь сам `claim()` — исправлено в `6f183ed`: rustdoc и ARCHITECTURE описывают это, а в `wp/WP-12.md` добавлен пункт: при отмене контроллер забывает `claim_id` и сопоставляет события по id.

## Мелкие

Ревьюер A:
- [мелкое] `arbiter.rs` — те же два пункта, что в «Важных» — исправлено (см. выше).
- [мелкое] `mdns.rs` `refresh_iface` — при ошибке `getifaddrs` адрес сбрасывался, а C++ сохранял прежнее состояние — исправлено в `6f183ed`: добавлена `pulsar_core::net::best_interface_checked() -> Result<Option<Iface>, ()>`, респондер при `Err` ничего не меняет. Это изменение чужого влитого крейта `pulsar-core` и его контракта (PROCESS п.3); ARCHITECTURE и «Заметки» PROGRESS обновлены.
- [мелкое] `bin/lan_probe.rs` — режим `claim` не показывал claims пира, пришедшие после решения, поэтому потеря и опоздание не различались — исправлено в `6f183ed`: оба claim-режима идут через `spawn_traced` и ещё 1 с после `Decided` печатают claims пира как `+N ms after own claim`.

Ревьюер B:
- [мелкое] `mdns.rs` — netlink в `select!` стоял после сокета 5353 — исправлено в `6f183ed`.
- [мелкое] mDNS — ответ на legacy-запрос больше запроса (усиление при подделанном источнике), нет ограничения частоты ответов из RFC 6762 — отказ: поведение унаследовано от C++ и записано в «Заметки» PROGRESS как известное ограничение.
- [мелкое] `mdns/dns.rs` `read_name` — длина имени не ограничивалась — исправлено в `6f183ed`: имя длиннее 255 байт на проводе отвергается (в C++ лимита не было), добавлен тест.
- [мелкое] `arbiter.rs` — `recent` не ограничен при потоке разных имён станций — исправлено в `6f183ed`: не больше 32 записей, вытесняется самая старая; тест.
- [мелкое] `mdns.rs` — смещения в netlink-сообщениях — магические числа — исправлено в `6f183ed`: compile-time `assert!` по `libc::nlmsghdr`/`libc::ifinfomsg`, комментарий к `NLMSG_HDRLEN`.
- [мелкое] `bin/lan_probe.rs` — рантайм без `max_blocking_threads(4)` (ARCHITECTURE «Модель исполнения» п.1) — исправлено в `6f183ed`.
- [мелкое] PROGRESS — не записаны изменения CLI и процедуры станций (`delay_ms`, без `dig`), известные ограничения и доля промахов арбитража — исправлено в `9cc174d`.
- [мелкое] нет теста goodbye при уничтожении handle — отказ (необязательный пункт): goodbye проверен на станциях (TTL 0 у обеих при выходе пробы), host-тест потребовал бы multicast из теста.

Раунд 2 (дельта `89b04cb..9cc174d`):
- [мелкое] изменение `pulsar-core` (`best_interface_checked`) лежит в общем коммите исправлений `6f183ed`, а не в отдельном `WP-03: fix pulsar-core: …`, как требует PROCESS п.3 — принято. Пакет вливается одним коммитом, поэтому изменение описано здесь: добавлена функция `pulsar_core::net::best_interface_checked()` (Err, если `getifaddrs` не удался), `best_interface()` теперь сделана поверх неё, поведение для прежних вызывающих не меняется.

## Отклонения от спеки и контракта

- В контракт `pulsar-lan` добавлены `mdns::spawn_traced` (`Answered`, `Reply`) и `arbiter::spawn_traced`. Это каналы наблюдения для `lan_probe`, контроллер их не использует (ARCHITECTURE, «Заметки» PROGRESS).
- `lan_probe claim-on-peer` получил аргумент `[delay_ms]`. Процедура спеки «ранний claim: Midi через 1 с» неисполнима: claim старше lookback 500 мс не учитывается. Спека WP-03 исправлена.
- `dig` (BIND 9.18) не принимает multicast-ответ с адреса станции, поэтому mDNS проверялся python `zeroconf`. Спека исправлена.
- Разбор уровня в датаграмме повторяет `sscanf`/`strtof` в десятичной записи (golden). Шестнадцатеричные float отвергаются, а glibc их принял бы; станции их не шлют.
- Golden-данные (`tests/golden/{mdns,arbiter}.txt`) получены из C++ `rust-port-base`, собранного на host (`zig c++ -std=c++20`), одноразовым harness с перехватом `sendto`/`recv`. Harness не коммитится.
