- Пакет: WP-06
- Коммит-база: `419427a` (`origin/rust` с захватом WP-06)
- Ревьюеры: A — «rv06a» (баги и паритет с C++), B — «rv06b» (архитектура, контракты, unsafe/FFI, конкурентность, ресурсы). Третий ревьюер только по unsafe (C) выбыл из-за rate limit; его область целиком взял на себя B.

## Блокирующие

- [блокирующее] `crates/pulsar-sendspin/src/service.rs` (A) — `sink.configure()`/`release()` выполнялись в акторе после возврата `ss_loop`, а sendspin-cpp сразу после `on_stream_start` вызывает `sync_task->signal_stream_start()`, и sync-задача тут же пишет 25 мс priming-тишины (`player_role.cpp:629-647`, `sync_task.cpp:233-236`) — до configure `write` возвращал `(length, 0, 0)` без отчёта, библиотека считала кадры буферизованными, тайминг сдвигался на ≥ 25 мс на каждом старте/рестарте потока — C++ делал configure внутри колбэка — исправлено в `b07933a`: запрос sink делается синхронно в колбэке главного цикла (`Ctx::event`) до постановки события в очередь; актор только логирует и ведёт удержание. Решение «событие → запрос sink» вынесено в чистую `event::sink_request` с host-тестом; тест с `sendspin_ffi` (`stream_callbacks_drive_the_sink_before_the_actor_runs`) тоже оставлен.

## Важные

- [важное] `crates/pulsar-sendspin/src/stub.rs` (B) — `SendspinHandle` заглушки был `Send + Sync` (только `Infallible`), а настоящий — `!Send` (`Rc`): host-сборка WP-12 могла бы скомпилировать то, что не соберётся со станционной — исправлено в `b07933a`: `PhantomData<Rc<()>>`.
