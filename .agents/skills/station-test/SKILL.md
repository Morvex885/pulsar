# Тест на живой станции

Правила — `docs/stations.md` (читать целиком до первого действия), реализация — `tools/station.sh`
(команды — в его usage), запреты — `AGENTS.md`, «Безопасность станций». Здесь только порядок
действий; условия, числа и пороги — по ссылкам.

## 1. Допуск

- Адрес станции и метка работы берутся из окружения: `PULSAR_MIDI`, `PULSAR_LITE2` или
  `PULSAR_MINI` и `PULSAR_TAG`; адреса в репозиторий не писать. Нет переменной — статус
  `заблокирован: нет PULSAR_<X>` (`docs/stations.md`, пункт «Адреса»), дальше не идти.
- `tools/station.sh` знает только `midi|lite2|mini`. Для Мини 2 и Мини 3 (модель уже поддержана) цели
  в нём нет: сначала добавить её (сам скрипт, перечни целей в этом skill и пункт «Громкость» в
  `docs/stations.md`; ключ dmix модели — `add-station-model`, п. 2, «Ключ dmix»). Для модели,
  неизвестной установщику, — skill `add-station-model`.
- Вызов: `PULSAR_TAG=<метка> tools/station.sh <midi|lite2|mini> <команда>`. Начать с `status`
  (ничего не меняет): кто держит lock, режим станции.

## 2. Lock

- `lock <минуты>`: срок честный (`docs/stations.md`, пункт «Lock»); для живой подмены — не меньше
  минимума оттуда.
- `break-lock` снимает только просроченный чужой lock или оборванный захват без `owner` (условия —
  в команде `break-lock` скрипта). Без явной просьбы пользователя не вызывать.

## 3. Остановка демона

- Аппаратные утилиты и тесты ESPHome API — только после `stop` (`docs/stations.md`, пункт
  «Аппаратные тесты»). Отказ `stop` — статус и действия из этого пункта, не обходить.
- Сетевые тесты без API (`lan_probe`, `update_probe get|check`, но не `install`) допустимы при
  работающем демоне по условиям `docs/stations.md`, пункт «Сетевые тесты без API».

## 4. Тестовый экземпляр

1. Сборка: `make -C satellite ARCH=<arch>` (`AGENTS.md`, «Сборка и проверки»).
2. Последовательность: `push satellite/build/<arch>/pulsar` → `stop` → `test-start` → тест →
   `test-stop` → `start`.
3. Клиент: `tools/esphome_check.py --host <ip> --port 16053 <command>`; команды (`dump`, `commands`,
   `voice-fake`, `announce`, `timer`, `set-key`, `scenario-*`) — в `--help` и docstring скрипта.
4. Лог тестового экземпляра: `test-log [N]`; лог демона: `log [N]`.
5. `test-start` кладёт в `/tmp/pulsar-test/` образы радио со станции поверх отправленных `push`;
   если образа на станции нет, отправленный остаётся, и тестовый экземпляр прошьёт им радио сам,
   без подтверждения. Для тестового экземпляра образы радио в `push` не отправлять, а отправленный
   для `zigbee_probe` (skill `zigbee-radio`) до `test-start` убрать (`cleanup`, затем снова `push`
   бинаря): новую сборку радио проверяют только через `zigbee_probe`.

## 5. Probe-утилиты

`make -C satellite ARCH=<arch> tools` → `satellite/build/<arch>/tools/<name>`
(`AGENTS.md`, «Сборка и проверки»); список — `docs/architecture.md`, «Workspace». `push` файла в
`/tmp/pulsar-test/`, запуск — `ssh "$PULSAR_<X>" /tmp/pulsar-test/<name> …` (то же ssh-назначение,
что у `station.sh`; команды запуска в нём нет). Утилиты со звуком — п. 6.

## 6. Звук

Только с согласия владельца, под пределом громкости из `AGENTS.md`, «Безопасность станций»; как
проверить громкость на модели — `docs/stations.md`, пункт «Громкость». Убит процесс во время
звука — обязательно `cleanup` (`docs/stations.md`, пункт «Убитый во время звука процесс»).

## 7. Живая подмена (необратимо для владельца)

- `swap <бинарь>` — только после явного подтверждения пользователя в этой сессии и под lock нужного
  срока.
- `stop` и `swap` делают `killall pulsar`, то есть убивают и тестовый экземпляр: перед `swap` —
  `test-stop`.
- Условия для Миди в роли `pulsar-coordinator` — `docs/stations.md`, пункт «Живая подмена». Не
  выполнены — не подменять, пункт в чек-лист владельца.
- Наблюдать за `log [N]`, затем обязательно `restore`.
