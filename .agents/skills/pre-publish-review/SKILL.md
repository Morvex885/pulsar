# Ревью перед публикацией

Обязательно перед `git push`, `gh pr create`, тегом `v*`. Правила — `AGENTS.md` («Правила кода»,
«Документация», «Git», «Безопасность станций»), `docs/architecture.md`.

`git push` и `gh pr create` — только по просьбе пользователя или с его явного подтверждения;
чистый раунд ревью сам по себе их не разрешает.

## Диапазон

`origin/main...HEAD` (скрипту — `origin/main..HEAD`, см. шаг 0) плюс контекст тронутых файлов
(читать файлы целиком вокруг изменений).
Для релиза — от прошлого тега (`git describe --tags --abbrev=0 --match 'v*'`).

## Шаг 0: авторство

`tools/check-authorship.sh origin/main..HEAD` (для релиза — от прошлого тега; в CI — job `commits`). Нарушение чинить:
`git commit --amend --reset-author` или rebase с удалением AI-трейлеров. Чужой `--author` не
подставлять. Переписывание уже запушенной истории и force push — только с согласия пользователя.
Перед `gh pr create` и после правки заголовка или описания PR — `tools/check-authorship.sh --text
<файл>` по файлу «заголовок, пустая строка, описание»: при squash они становятся сообщением коммита
в main. До кода 0 дальше не идти.

## Оси (у каждой свой независимый ревьюер)

1. **Авторство и приватность**: скрипт; в диффе нет IP, MAC, серийников, токенов, логов станций и
   ничего из `backup/ dump/ re/ ref/`.
2. **Сборка и тесты**: `make -C satellite check`; installer — `go -C installer vet ./...` и
   `go -C installer test ./...`; radio — `radio/build.sh`; ssh — `ssh/build.sh`.
3. **Код**: логика, гонки, краевые случаи, обработка ошибок, устаревшие id событий.
4. **Архитектура**: соответствие `docs/architecture.md` и `AGENTS.md`, «Правила кода».
5. **Безопасность**: вход из сети (ESPHome, deCONZ, Sendspin, UDP арбитра, HTTPS апдейтера),
   проверка скачиваемых ассетов.
6. **Безопасность станций**: `AGENTS.md`, «Безопасность станций».
7. **Доки и язык**: нет пересказа кода, у кода «почему», факт в одном месте, ссылки и якоря живые,
   язык по правилам, `README.md` не устарел.
8. **Тесты по сути**: чистая логика (`logic.rs`, `led_fx`, `clock_fx`) покрыта, golden-тесты FMA не
   перепинены без причины.

## Раунд

- Каждую ось проверяет независимый ревьюер: параллельный агент, если харнесс умеет; иначе по
  очереди, каждый раз заново читая дифф.
- Формат замечания: `файл:строка | серьёзность | доказательство | правка`.
- Все замечания к исправлению исправить; следующий раунд — снова все оси. Конец — полный раунд без
  замечаний к исправлению. Лимита раундов нет.
- Вне рамок задачи: не править молча, собрать списком для пользователя.

## Итог

Число раундов и список вне рамок. Затем — `push` / `gh pr create` по подтверждению пользователя
(тег — по skill `release`).
